invariants-first

A ratchet for your API rules.
A change can tighten them freely, but loosening one — by a person or a coding agent — fails CI until a reviewer says yes.

Value Laws (Pydantic + OpenAPI + CEL) Path Laws (Static Call-Graph Scan) Runtime Guards + Ablation Alpha 0.1.0 • Apache-2.0

0:00 – 1:00: Lead with the ratchet thesis, not "a CEL/AST framework." Every developer who works with coding agents or LLM tool-calling recognizes the failure mode immediately.

1. Hook (2 min)

The "Tests Pass, Production Breaks" Failure Mode

Coding Agents in PRs

Agents optimize to make the test suite green. When a rule is in the way, they:

  • Raise a limit (le=50_000 → 500_000) or widen a schema
  • Delete an assertion or validation check
  • Call StripeGateway.refund() directly to skip BillingService.refund()

Every diff looks plausible in review. All tests pass.

LLM Agents at Run Time

The twin failure mode: valid shape, invalid behavior.

  • Model emits valid JSON matching your Pydantic schema
  • Refunds another customer's order or exceeds remaining_cents
  • Or ledger state shifts between planning and execution

JSON Schema checks shape — not reality.

1:00 – 3:00: Contrast the two failure modes: coding-agent drift in CI vs. semantic/held-data violations by LLM agents at runtime.

2. Core Idea (3 min)

Separate Shape, Laws, and Bodies

Every layer of a system is an API: HTTP route, service method, repository, model call, payment gateway.

ConcernWho Owns ItWhat Lives Here
Shape Pydantic / OpenAPI Types, field bounds, Literals, enums
Laws People (invariants.yaml + invariants.lock) Value laws (inputs/outputs never allowed) & Path laws (which API may call which)
Bodies People or coding agents Implementations inside functions — agents are free to rewrite
Path laws hold on the API boundary regardless of what sits behind the sink: SQLAlchemy, Django, MongoDB, Stripe, or raw SQL.

3:00 – 5:30: Highlight the division of labor: humans lock the boundary laws; coding agents keep full freedom inside function bodies.

2. Core Idea (continued)

How the One-Way Ratchet Works

1. Day-1 Lock

inv init reads your existing code with zero hand-written rules:

  • Pins Pydantic constraints into contracts
  • Discovers service → repo door rules
  • Freezes legacy back doors in allow: so CI passes on day 1

2. Tighten Freely

Narrow a limit, tighten a CEL rule, or add a new invariant:

  • Run inv lock
  • inv check --base main sees 0 weakenings
  • Passes automatically — no human bottleneck

3. Loosen → Human Gate

Raise a cap, widen a type, delete a rule, or add a bypass:

  • Even if the agent runs inv lock --accept-weakening, inv check --base main compares against main and fails
  • Only a reviewer (e.g. PR label) can accept

5:30 – 7:30: Emphasize why comparing against --base main defeats self-re-pinning: an agent cannot hide a weakening by updating invariants.lock.

4. Path Laws Without the Noise

Quiet on Day One: Diff-First Scan + Run-Time Door Check

Two Tiers in inv check

  • Blocks: a call that skips a door, getattr on a sink, __wrapped__, monkeypatching
  • Warns: a call the scan can't follow (an untyped x.save())
  • Diff-first with --base main: a site already on main warns; one the PR adds fails
  • strict: true on a rule, or --strict-scan, for sinks that need every site reviewed

Run-Time Backstop: pytest --inv-doors

  • A door marks itself active while it runs; a sink checks that one of its doors is
  • Catches getattr, DI containers and callbacks on every path the tests run
  • A tool reaching StripeGateway.refund through getattr fails the session, even if the test swallowed the error
  • inv.doors.install(mode="detect") for staging
$ inv check --base main
  ok    scan: no path skips a door or guard
        WARN  unresolved/inferred-path  ... [on main]
# an agent adds a new untyped call into the store:
  FAIL  scan
        unresolved/inferred-path  ... insert_lease  [new since main]

The static scan stays simple and quiet: legacy dynamic calls are warnings, so there is no day-one annotation tax, but an agent can't add a new one unnoticed. The run-time door check covers what static analysis of Python can't follow. Start with the one to three sinks an agent must never reach directly.

6. Honest Limits & Next Steps

Boundaries & How to Start

Honest Boundaries (Preempting Q&A)

  • Nothing below the API: Concurrency races (R-20 stays enforce(known-callers) due to residual_paths; DB triggers handle races) & buggy providers.
  • Dynamic Python: Arbitrary eval / C-extension dispatch is out of scope for static AST scanning.
  • Evaluation & Alpha Status: Self-authored apps/defects with fake/replay models. An external audit’s findings were each reproduced with a failing test before being fixed (round 35); 109 of 110 hand-written mutants of the fixes are caught (the last is equivalent).

3-Step Adoption

# 1. Start with zero prod code changes
inv init
inv check --base main

# 2. Protect critical boundaries
@inv.model_call / @inv.edge / @inv.guard

# 3. Prove guards are load-bearing
pytest --inv-verify --inv-ablate

Demo script: ./presentation/demo.sh all
